# Gate 3 architecture — Canonical Music Map v1

Gate 3 converts admitted canonical PCM into a deterministic, content-addressed
Music Map. The authoritative path is integer/fixed-point C11: no host floating
point, architecture-specific FFT library, wall clock, hidden decoder state or
probabilistic inference can define canonical truth.

## Canonical audio and resampling

The only analysis rate is 48,000 samples/second, stereo signed Q1.31. A 48 kHz
input takes a bit-exact bypass. Other admitted rates use a deterministic
polyphase FIR/Lanczos plan with 1024 phases, 64 base taps scaled by
`ceil(input_rate / 48000)` and capped at 512 taps. Coefficients are signed Q30,
each phase row is corrected to sum exactly to `1 << 30`, and every complete
table is bound to SHA-256.

The cutoff is the exact rational `23/25 * min(1, 48000/input_rate)`. Sine is
produced by an integer CORDIC contract. Accumulation uses the engine's portable
full-width integer arithmetic rather than compiler-specific `__int128` as a
semantic dependency. Output length is the exact rational 48 kHz ceiling;
phase/index mapping is checked against overflow. Cancellation is cooperative and
accepted cancellation prevents successful publication. Saturation is explicit
and counted.

An independent Python implementation regenerates every coefficient for the
44.1, 96 and 384 kHz canonical oracle plans and compares all 720,896 coefficients
byte-for-byte, then validates table identity and output behavior.

## Exact Music Map coordinate system

The map rate is exactly 100 Hz: one tick per 480 canonical samples. Tick `N` is
anchored at canonical sample `N * 480`. Analysis uses a centered 2048-sample
window with deterministic zero extension outside the source extent. Timeline
indexing is unsigned and checked so even extreme `uint64_t` coordinates cannot
invoke signed overflow.

The analysis plan freezes a periodic Hann window and 2048-point radix-2 FFT.
Window coefficients and complex twiddles are generated by integer CORDIC and
stored as Q1.31. The FFT has 11 stages and divides by two at every stage with
nearest-ties-away-from-zero rounding, keeping the transform bounded and fully
specified.

## Exact feature vector

Each 128-byte canonical tick contains exact, versioned numeric facts:

- RMS for left, right, mid and side;
- six contiguous spectral-band energies with frozen bin edges
  `[0, 6, 11, 22, 86, 342, 1025]`;
- total spectral energy;
- three deterministic envelope states with divisors `[4, 16, 64]`;
- spectral flux against explicit previous-spectrum state;
- spectral centroid in bin Q16.16;
- signed energy delta;
- silence state with threshold exactly `1/1024` full-scale;
- stereo balance Q1.31;
- normalized stereo width Q1.31.

Sequential features never consult hidden global state: the caller owns the
analysis state and scratch storage. Canonical tick publication is transactional.

Onset, beat, BPM, phrase, section and semantic labels are explicitly inference,
not exact Music Map facts. A future inference layer must be versioned and
confidence-bearing and may never overwrite the canonical map.

## Music Policy identity

The mathematical policy is serialized into exactly 192 canonical bytes and
SHA-256-addressed. The current reconstructed Music Policy v1 digest is:

`cbe9ccd31eeaa27be0113f8c3481f79a48cbd08bf318adefaa665ab8fa8efaec`

The policy record binds the sample/tick/window/FFT geometry, band layout,
envelope/silence rules, resampling contract and analysis table identities. A
policy change changes the digest even when the outer schema remains compatible.
The digest is therefore semantic identity, not merely a human version label.

This hash is evidence for this reconstructed Gate 3 source. It is not claimed to
be byte-identical to the unfinished Work-session policy whose final bytes were
never persisted.

## `analysis.bin`

The canonical Music Map record uses the generic 64-byte ODMC envelope. Its
payload begins with a fixed 128-byte map header containing:

- `ODMMAP1\0` magic and schema 1.0;
- canonical sample/tick/window/bin/band geometry;
- fixed tick-record size of 128 bytes;
- tick count and canonical frame count;
- SHA-256 of the canonical PCM bytes;
- SHA-256 of the canonical Music Policy.

The remaining payload is exactly `tick_count * 128` bytes of little-endian tick
records. Size is computed before writing. Writer validation rejects inconsistent
tick count, centers, reserved bytes, centroid/range violations and policy
self-identity failures.

Reading is fail-closed and two-pass. The ODMC payload digest, kind/schema,
canonical geometry, expected policy, exact extent and every tick are validated
before caller-visible ticks are published. A corrupt, truncated, trailing,
unknown-version, correctly re-hashed but semantically invalid record cannot
partially publish decoded state.

## Independent oracle

`tools/check_music_analysis_oracle.py` independently reimplements CORDIC, Hann,
Q1.31 multiply/rounding, scaled radix-2 FFT, RMS/energy, all six bands,
envelopes, flux, centroid, delta, silence and stereo features. It also constructs
the 192-byte policy, 128-byte tick records, 128-byte map header and 64-byte ODMC
envelope without using engine analysis code for expected values.

The canonical oracle compares all 2048 Hann coefficients, all 1024 complex
twiddles, three complete feature ticks, the policy bytes and the entire
`analysis.bin` byte-for-byte. Its current full-record SHA-256 is:

## Certification boundary

All Gate 3 capabilities remain `implemented_uncertified`. The evidence proves
specified deterministic behavior on the exercised compiler/runtime matrices; it
is not an external certification, perceptual quality claim or proof over every
possible input. Direct libav integration remains outside the evidence host
because development packages are absent, as recorded by Gate 2.
